# 安装、更新与停用

## 安装插件

插件发布后，将插件页面地址发给 wecode，提出你的实际需求，例如：

> 请把这个 JSON 检查插件获取到当前工作区，阅读说明并安装。用一个正常文件和一个错误文件验证它，告诉我如何使用。

助手先取得完整插件目录，再执行安装。当前仓库不是 wecode 已内置的远程市场入口。请在本地工作区会话中完成这一流程；远端工作区的源码传输尚未接入时，不把下载完成当成安装成功。

安装后至少验证一次真实功能：输入测试文件，等待处理结束，再打开报告核对结果。只显示“已启动”不能证明任务成功。

## 更新插件

请 wecode 检查更新说明，在保留当前可用版本的前提下升级，并重新运行测试。升级失败时应保留原版本和错误记录，不把失败或未知状态当成成功。不要手动改写安装记录。

## 停用插件

告诉 wecode 要停用哪个插件，并确认之后不能再发起新调用。正在进行的工作需要正常收尾。

停用不等于删除：历史记录、插件状态和已产生的文件可能仍然保留。不要通过删除宿主数据库来卸载插件。

## 如何判断“已验证”

- 源码检查：文件完整、打包内容明确、自动化测试通过。
- 宿主验证：在明确记录的 wecode 版本与操作系统上，实际安装并运行过插件，确认处理正常结束，输出符合预期。
- 生命周期验证：更新、停用、重新启动等结果分别记录；没有运行的项目保持未验证。

每次发布只描述实际完成的验证。校验和用于发现文件变化，不能替代真实运行，也不能保证插件没有恶意行为。只安装你信任的插件。

开发插件时，让当前安装的 wecode 提供相应版本的作者规范；本公开指南不复述宿主内部协议或私有实现。

开发者验证记录中的宿主身份可以是确切源码提交，也可以是实际执行文件的 SHA-256 指纹（`sha256:` 前缀）。定制构建应记录真实文件指纹，不冒充某个完整源码提交的构建；身份记录仍须结合真实运行结果审查。
